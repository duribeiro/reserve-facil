# Etapa 4c. Amostras visuais

**Objetivo:** Mostrar ao dono três caminhos visuais reais, com cara de app pronto, para ele escolher ou misturar antes de construir o design system.

| | |
|---|---|
| Entra | `references.md` da etapa 4b, o wireframe aprovado e `design-rules.md`. |
| Sai | Três amostras na ferramenta de desenho (três telas-chave cada), as imagens de conteúdo usadas, e a decisão do dono registrada em `pipeline/decisions/`. |
| Quem decide | O dono escolhe uma amostra ou uma mistura. Ponto de decisão visual. |
| Roteiro do agente | [prompt.md](prompt.md) |

**Critério de aceite:** três amostras com estrutura diferente entre si (não só troca de cor), conferidas por captura, e a escolha do dono registrada como decisão.

Gerar imagem pode custar. O agente só gera depois de o dono aprovar o custo estimado.

Regras que valem em toda etapa: [pipeline/README.md](../README.md) e [question-principles.md](../question-principles.md).
