# Etapa 4b. Referências visuais

**Objetivo:** Antes de desenhar a alta fidelidade, saber como apps bons do mesmo tipo resolvem cor, tipografia, imagem e componentes, e transformar isso numa especificação visual.

| | |
|---|---|
| Entra | `vision.md`, `journeys.md`, `scope.md`, o wireframe aprovado e `design-rules.md`. Opcional: uma pasta ou lista de referências que o dono já tenha. |
| Sai | `references.md` (briefing visual, referências numeradas com o que vale e o que fica fora, e a especificação extraída) e a pasta `refs/` com as imagens baixadas. |
| Quem decide | O agente pesquisa, avalia e extrai. O dono só opina se quiser, ou nas referências que ficaram em dúvida. |
| Roteiro do agente | [prompt.md](prompt.md) |
| Apoio | [regua.md](regua.md) (portões medidos, notas com âncora, testes) e [fontes.md](fontes.md) (onde pesquisar, por nível de confiança) |

**Critério de aceite:** pelo menos 8 referências avaliadas pela régua de critérios, cada uma com o que vale e o que fica fora, e uma especificação visual com cores, tipografia, raios, imagem, componentes e clima.

As imagens de referência servem só para estudo. Nunca entram no produto, e nenhuma marca, logo ou identidade de terceiros é copiada.

Regras que valem em toda etapa: [pipeline/README.md](../README.md) e [question-principles.md](../question-principles.md).
